# Tenlith implementation plan

> **For agentic workers:** Use superpowers:executing-plans or subagent-driven-development. Independent web and API tasks may run in parallel under dispatching-parallel-agents.

**Goal:** Ship a usable, polished, locally runnable .NET + React SaaS starter.
**Architecture:** A modular ASP.NET Core monolith, PostgreSQL and a React SPA served behind a same-origin proxy. Vertical slices own their endpoints; tenant membership is checked server-side.
**Tech Stack:** .NET 10 LTS, EF Core, Identity, JWT, React 19, TypeScript, Vite, PostgreSQL, Docker Compose.
**Spec:** ../specs/2026-11-10-tenlith-design.md

## Global constraints

- MIT, English UI/docs, Tenlith namespaces, no paid requirement for local demo.
- No production simulation or seeded credentials, no token persistence in browser storage.
- Keep runtime secrets out of tracked files and restrict localhost infrastructure ports.
- No public publication or invented demo links/badges. No generated commit trailers.

## Shared contract

See ../../api-contract.md for JSON payloads and routes. API owns `src/Tenlith.Api` and `tests/Tenlith.Api.Tests`; web owns `src/Tenlith.Web`. Infrastructure/docs owner edits only root, `.github`, `docs`, `scripts`, and `assets`.

## Review focus

1. Accessing an object in another tenant returns denial even with its valid ID.
2. A stale refresh token revokes its entire token family, including its successor.
3. Invitations cannot be consumed by a different email or replayed after use.
4. Quota checks serialize competing writes; paid entitlements require verified state.
5. Empty/error/mobile states remain usable, and unconfigured services fail clearly.
